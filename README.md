# 数据分析实验与数据应用服务平台

面向指标口径管理、分析实验设计、OLAP查询、数据看板构建与数据API发布的数据应用平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 取证封存

在数据快照之上新增取证封存：登记时读取损益数据的分区范围与每个分区的校验记录，
对账人逐分区签确认后，封存件从 **待核对** 流转到 **已封存** 或 **待作废**。

- **状态流转**：待核对 → 已封存（证据齐备：每分区校验记录 + 对账确认齐全）；
  待核对/已封存 → 待作废（申请作废或登记分区更正）；待作废 → 已封存（隔离分区重签后恢复）
  或 → 已作废（确认作废）。已作废的封存件保留在册，仍可审计，不再交付。
- **证据口径**：封存状态必须关联完整证据；重复确认幂等，不增加证据份数；
  待核对状态不能跳过签确认直接交付；同一快照编号可多次取证，按封存序号（第 N 次）
  与证据编号（`EV-<快照编号>-<序号>-<分区号>`，重签后追加 `-R<轮次>`）分清各次封存。
- **交付政策（已明确）**：采用 **有效分区补充件交付**。封存发出后若某分区因确认人
  签错范围被隔离，其余仍有效的分区可先以补充件交付给新申请；被隔离分区的证据编号
  进入隔离清单，不再随旧封存件发给任何新申请；该分区按更正后范围重签生效后，以新的
  证据编号回到交付清单。不采用「整件重签前暂停一切交付」。
- **清单与核对**：`GET /api/forensic/{id}/manifest` 给出交付清单（可交付状态、可交付
  证据、隔离证据），数据导出在「开始导出」时消费该清单，不可交付一律拦下；快照恢复
  （恢复封存）时交付清单随之更新。已领取的原件通过
  `GET /api/forensic/{id}/receipts/{领取编号}/verify` 核对领取时的证据，通过
  `GET /api/forensic/{id}/receipts/{领取编号}/compare` 与一份新申请对照后者可取的
  分区和证据编号。
- **模拟核对**：`cd backend && .venv/bin/python -m tests.forensic_flow` 复用一个快照
  编号发起两次封存确认，模拟封存后签错与后续恢复，逐项核对状态变化和可交付清单。
